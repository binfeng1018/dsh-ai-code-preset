# AI 编程工作台

BISHENG / DeepSeek Harness Desktop 工作台插件，版本 **0.1.4**。

将本地项目文件树、轻量文本编辑器和宿主原生 AI 会话组合为三栏工作区。

## 功能

- 浏览用户明确选择的本地项目目录。
- 新建文件（现有父目录、不覆盖同名文件）、确认后永久删除文件（带磁盘版本检查）。
- 按文件名/相对路径或文本内容进行大小写不敏感的字面量搜索，结果可点击打开；内容结果显示行号和摘要。搜索有扫描边界且最多返回100项，跳过 node_modules、Git 内部、凭证和链接。
- 多文件标签、UTF-8 文本编辑、行号、Tab 缩进、⌘/Ctrl+S 保存。
- 读取时的磁盘基线与当前编辑全文对照；已保存文件相对 Git HEAD 的差异。
- 原生 AI 会话、命令执行、测试输出与审批继续使用宿主能力。
- 文件目录和 AI 助手的边界均可拖动调宽；方向键微调，Shift 加速，双击恢复默认。
- 窄窗口上下排列；原生会话区域排除工作台 CSS，避免按钮和标签样式冲突。

## 构建与测试

需要 Node.js 和 pnpm，不需要下载客户端构建依赖。

```bash
pnpm run build
pnpm test
pnpm run check
pnpm pack
```

客户端源码为 `src/client.js`，构建后的 `lib/client.js` 随仓库提交，供宿主模块加载器直接使用。服务端入口为 `dsh/index.js`，文件 API 为 `dsh/files.mjs`。

`package.json` 已声明仓库身份 `binfeng1018/dsh-ai-code-preset`。npm 包名仍为 `dsh-ai-coding-workbench-local`，不代表已经发布到 npm 或工作台市场。

## 安装

本机验证环境为 BISHENG Desktop 1.2.0、macOS arm64。该安装版实际使用 `web` profile；其他版本可能不同，安装前须确认目标应用的 profile，不要照搬到无关环境。

使用目标安装版提供的 DSH CLI 安装 `pnpm pack` 生成的本地 tgz：

```bash
dsh plugin --profile <应用实际使用的-profile> add /absolute/path/to/dsh-ai-coding-workbench-local-0.1.4.tgz
```

本机安装曾通过应用打包的 Node/DSH CLI 成功执行。若 `dsh` 不在 PATH，需使用目标应用正式提供的 CLI 路径，不能直接用其他 DSH 实例替代。特定企业配置也提供原生“安装本地工作台”目录选择入口，普通市场界面不一定显示。

安装后由用户完整退出并重新打开应用，在左侧工作台切换菜单选择 **AI 编程工作台**。卸载不会主动删除用户项目文件。

## 使用

1. 点击“打开项目”，通过宿主目录选择器选择已有项目。取消不创建工作区或会话。
2. 点击文件编辑；保存时校验 SHA256 基线，磁盘有外部变更则拒绝覆盖。
3. 使用“编辑对比”查看全文基线/当前缓冲；使用“Git 变更”查看已保存内容相对 HEAD 的 diff。
4. 点击“新建项目会话”启用原生 AI。仅当会话工作区与左侧项目相符时显示对话，避免跨项目操作。
5. AI 改写磁盘文件后点击“重读”。先复制尚未保存的编辑，再重读并人工合并。
6. 拖动左右两条分隔线调整宽度；窄窗口右侧变为上下布局，不提供横向调宽。

## 安全与限制

- 文件读写、删除仅支持最大 1MiB UTF-8 文本，不支持二进制；新建文件的父目录必须已存在。
- 删除不经过废纸篓，无法在工作台撤销；操作前会确认，磁盘版本已改变则拒绝删除。
- 搜索只查询已保存内容，不含编辑缓冲，内容结果不会自动跳转到对应行。
- 拒绝路径穿越、符号链接、硬链接、`.git` 内部与凭证类路径。
- 使用乐观版本检查、进程内写锁、临时文件及原子重命名保存；保留文件模式。
- Node 可移植 API 无法防御恶意外部进程在检查和 rename 之间替换目录，因此仅用于可信本地项目，不是多租户文件服务。
- Git diff 使用有界、无 shell 的 `execFile`，没有任意命令 HTTP 接口。
- 没有独立终端、LSP、自动补全、语法诊断、格式化、目录创建/删除、重命名、Git 提交或自动回滚。
- 编辑对比为整份内容红/绿对照，不是最小行级 diff。
- 项目、未保存缓冲及侧栏宽度不跨应用重启持久化；离开前请保存。
